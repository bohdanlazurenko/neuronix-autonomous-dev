# Data Model: Neuronix Autonomous Development System

**Created**: 2025-10-18  
**Phase**: 1 - Design & Contracts  
**Purpose**: Define key entities, their attributes, relationships, and state transitions

## Overview

Neuronix operates on a set of core entities representing the workflow from brief submission to deployed application. All entities are transient (not persisted to database) and exist only during the request lifecycle, with final artifacts stored in GitHub repositories.

## Core Entities

### 1. Brief

**Description**: Natural language project description submitted by user

**Attributes**:
- `content`: string - The natural language project description
- `language`: 'en' | 'ru' - Detected language of the brief
- `submittedAt`: timestamp - When the brief was submitted
- `userId`: string | null - User identifier (optional, for future auth)

**Validation Rules**:
- `content` must be 10-5000 characters
- `content` must not contain malicious scripts or SQL injection patterns
- `language` auto-detected from content, defaults to 'en'

**Relationships**:
- Creates → 1 ProjectRequest

**State Transitions**:
```
[Submitted] → [Validated] → [Passed to PM Agent]
                ↓
           [Rejected] (if validation fails)
```

---

### 2. ProductRequirementsDocument (PRD)

**Description**: Structured product specification generated by PM Agent

**Attributes**:
- `id`: string (UUID) - Unique identifier
- `projectName`: string - Kebab-case project name (e.g., "habit-tracker")
- `goal`: string - Primary project objective
- `features`: string[] - List of features to implement
- `techDecisions`: TechDecisions - Stack and architecture decisions
- `createdAt`: timestamp - When PRD was generated
- `generatedBy`: 'PMAgent' - Agent that created this

**Type: TechDecisions**:
```typescript
{
  framework: string        // e.g., "Next.js 14"
  language: string         // e.g., "TypeScript"
  styling: string          // e.g., "Tailwind CSS"
  dependencies: string[]   // Key libraries needed
}
```

**Validation Rules**:
- `projectName` must be kebab-case, 3-50 characters
- `features` must contain 1-20 items
- `goal` must be 20-500 characters
- All fields required (no nulls)

**Relationships**:
- Generated from → 1 Brief
- Feeds into → 1 ImplementationPlan

**State Transitions**:
```
[Generating] → [Generated] → [Validated] → [Passed to Dev Agent]
                   ↓
              [Failed] (if JSON parsing fails)
```

---

### 3. ImplementationPlan

**Description**: Detailed technical plan with file structure

**Attributes**:
- `id`: string (UUID) - Unique identifier
- `projectName`: string - Same as PRD project name
- `stack`: TechStack - Complete tech stack specification
- `files`: FilePlan[] - List of files to generate
- `createdAt`: timestamp - When plan was created
- `generatedBy`: 'PMAgent' - Agent that created this

**Type: TechStack**:
```typescript
{
  framework: string
  language: string
  styling: string
  testing: string
  deployment: string
}
```

**Type: FilePlan**:
```typescript
{
  path: string          // Relative file path (e.g., "app/page.tsx")
  purpose: string       // What this file does
  dependencies: string[] // Other files it depends on
}
```

**Validation Rules**:
- `files` must contain 5-50 items
- File paths must be valid (no `..`, absolute paths, or special chars)
- Must include mandatory files: `package.json`, `README.md`, `.gitignore`, `tsconfig.json`
- Must include health check endpoint: `app/api/ping/route.ts`

**Relationships**:
- Derived from → 1 PRD
- Feeds into → 1 CodeGeneration

**State Transitions**:
```
[Planning] → [Planned] → [Validated] → [Passed to Dev Agent]
                ↓
           [Invalid] (if mandatory files missing)
```

---

### 4. GeneratedFile

**Description**: Single source code file generated by Dev Agent

**Attributes**:
- `path`: string - Relative file path in project
- `content`: string - Complete file contents
- `language`: string - File language/type (e.g., "typescript", "json", "markdown")
- `size`: number - Content size in bytes
- `createdAt`: timestamp - When file was generated

**Validation Rules**:
- `path` must not contain `..` (directory traversal)
- `content` must not contain placeholder TODOs
- TypeScript files must have valid syntax (linted)
- JSON files must be valid JSON
- `size` must be <100KB per file

**Relationships**:
- Part of → 1 CodeGeneration
- Committed to → 1 Repository

**State Transitions**:
```
[Generating] → [Generated] → [Validated] → [Committed to GitHub]
                   ↓
              [Failed] (if syntax errors)
```

---

### 5. CodeGeneration

**Description**: Complete set of generated files for project

**Attributes**:
- `id`: string (UUID) - Unique identifier
- `projectName`: string - Same as plan project name
- `files`: GeneratedFile[] - All generated files
- `totalFiles`: number - Count of files
- `totalSize`: number - Total size in bytes
- `createdAt`: timestamp - When generation completed
- `generatedBy`: 'DevAgent' - Agent that created this

**Validation Rules**:
- `files` must match `ImplementationPlan.files` (all planned files present)
- `totalFiles` must be 5-50
- `totalSize` must be <10MB
- Must include all mandatory files
- All TypeScript files must pass `tsc --noEmit` check

**Relationships**:
- Generated from → 1 ImplementationPlan
- Creates → 1 Repository

**State Transitions**:
```
[Generating] → [Generated] → [Validated] → [Ready for Deployment]
                   ↓
              [Failed] (if validation fails)
```

---

### 6. Repository

**Description**: GitHub repository containing generated code

**Attributes**:
- `id`: string - GitHub repository ID
- `name`: string - Repository name (same as project name)
- `owner`: string - GitHub username/organization
- `url`: string - Full GitHub URL (e.g., "https://github.com/user/project")
- `defaultBranch`: string - Usually "main"
- `visibility`: 'public' | 'private' - Repository visibility
- `createdAt`: timestamp - When repo was created

**Validation Rules**:
- `name` must be valid GitHub repo name (kebab-case, no special chars)
- `url` must be valid HTTPS URL
- `visibility` defaults to 'public'

**Relationships**:
- Contains → N GeneratedFiles
- Created from → 1 CodeGeneration
- Triggers → 1 Deployment

**State Transitions**:
```
[Creating] → [Created] → [Committing Files] → [Committed] → [Deployed]
                ↓
           [Failed] (if GitHub API error)
```

---

### 7. Deployment

**Description**: Live hosted application deployment

**Attributes**:
- `id`: string - Deployment ID
- `projectName`: string - Same as repository name
- `deployUrl`: string - Live application URL (e.g., "https://project.vercel.app")
- `previewUrl`: string - Preview deployment URL
- `status`: 'pending' | 'building' | 'ready' | 'error' - Current status
- `createdAt`: timestamp - When deployment started
- `completedAt`: timestamp | null - When deployment finished

**Validation Rules**:
- `deployUrl` must be valid HTTPS URL
- `status` must transition in order: pending → building → ready
- Max wait time: 180 seconds (3 minutes)

**Relationships**:
- Deployed from → 1 Repository
- Part of → 1 ProjectRequest

**State Transitions**:
```
[Pending] → [Building] → [Ready] → [Accessible]
               ↓
           [Error] (if build fails)
```

---

### 8. ProgressEvent

**Description**: Real-time status update sent via SSE

**Attributes**:
- `id`: string (UUID) - Unique event ID
- `projectId`: string - Associated project request ID
- `type`: EventType - Type of event
- `message`: string - Human-readable status message
- `phase`: 'brief' | 'prd' | 'plan' | 'code' | 'repo' | 'deploy' - Current phase
- `progress`: number - Percentage (0-100)
- `artifact`: object | null - Associated artifact (PRD, file, URL)
- `timestamp`: timestamp - When event occurred

**Type: EventType**:
```typescript
type EventType = 
  | 'phase_start'
  | 'phase_complete'
  | 'artifact_generated'
  | 'error'
  | 'complete'
```

**Validation Rules**:
- `progress` must be 0-100
- `phase` must advance sequentially
- `type` = 'error' requires error details in message

**Relationships**:
- Part of → 1 ProjectRequest
- Streams to → Frontend UI

**State Transitions**:
```
[Created] → [Sent via SSE] → [Displayed in UI]
```

---

### 9. ProjectRequest

**Description**: Complete end-to-end project creation request

**Attributes**:
- `id`: string (UUID) - Unique request ID
- `brief`: Brief - Original brief
- `prd`: ProductRequirementsDocument | null - Generated PRD
- `plan`: ImplementationPlan | null - Implementation plan
- `code`: CodeGeneration | null - Generated code
- `repository`: Repository | null - Created repository
- `deployment`: Deployment | null - Live deployment
- `status`: RequestStatus - Overall status
- `startedAt`: timestamp - When request started
- `completedAt`: timestamp | null - When request finished
- `error`: string | null - Error message if failed

**Type: RequestStatus**:
```typescript
type RequestStatus =
  | 'submitted'
  | 'analyzing'
  | 'planning'
  | 'coding'
  | 'deploying'
  | 'completed'
  | 'failed'
```

**Validation Rules**:
- Lifecycle must complete within 900 seconds (15 minutes)
- Must transition through all statuses sequentially
- `completedAt` must be set when status = 'completed' | 'failed'

**Relationships**:
- Contains → 1 Brief
- Contains → 1 PRD
- Contains → 1 ImplementationPlan
- Contains → 1 CodeGeneration
- Contains → 1 Repository
- Contains → 1 Deployment
- Emits → N ProgressEvents

**State Transitions**:
```
[Submitted] → [Analyzing] → [Planning] → [Coding] → [Deploying] → [Completed]
                                                                       ↓
                                                                  [Failed]
                                                                  (at any stage)
```

**State Machine**:
1. **Submitted**: Brief validated, request created
2. **Analyzing**: PM Agent generating PRD
3. **Planning**: PM Agent creating implementation plan
4. **Coding**: Dev Agent generating source code
5. **Deploying**: Integration Agent creating repo + deploying
6. **Completed**: All phases successful, URLs available
7. **Failed**: Error occurred, partial artifacts may exist

## Data Flow

```
1. User submits Brief
   ↓
2. System creates ProjectRequest
   ↓
3. PM Agent generates PRD from Brief
   ↓
4. PM Agent generates ImplementationPlan from PRD
   ↓
5. Dev Agent generates CodeGeneration from ImplementationPlan
   ↓
6. Integration Agent creates Repository from CodeGeneration
   ↓
7. Integration Agent creates Deployment from Repository
   ↓
8. System marks ProjectRequest as Completed
   ↓
9. User receives Repository URL + Deployment URL
```

Throughout this flow, **ProgressEvents** are emitted at each phase transition and sent to the frontend via SSE.

## Persistence Strategy

**Important**: Neuronix is a **stateless system**. No entities are persisted to a database.

- **Brief**: Lives only in API request memory
- **PRD, Plan, Code**: Generated on-the-fly, not stored
- **Repository**: Persisted by GitHub (external system)
- **Deployment**: Managed by Vercel (external system)
- **ProgressEvents**: Streamed via SSE, not persisted

**Future Enhancement**: If persistence is needed (e.g., for history, analytics), add PostgreSQL or MongoDB with the following tables:
- `project_requests` (id, brief, status, created_at, completed_at)
- `artifacts` (request_id, type, content, created_at)
- `events` (request_id, type, message, timestamp)

## Error Handling

Each entity can enter an **error state** if validation fails:

- **Brief**: Malicious content detected → Reject with 400 error
- **PRD**: Invalid JSON from agent → Retry up to 3 times
- **Plan**: Missing mandatory files → Reject, request regeneration
- **Code**: Syntax errors in TypeScript → Retry generation
- **Repository**: GitHub API failure → Retry with exponential backoff
- **Deployment**: Build failure → Report error, provide repo URL anyway

**Error Recovery Strategy**:
1. Retry transient failures (API timeouts, network issues)
2. Reject permanent failures (validation errors, malicious input)
3. Provide partial results when possible (e.g., repo URL even if deployment fails)
4. Log all errors for debugging
5. Send error events via SSE to keep user informed
